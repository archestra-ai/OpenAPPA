# Answer key, scenario S1 (judge only; never shown to the simulator)
Score each answer 1 (correct), 0.5 (partly correct or vague), 0 (wrong, "don't know", or contradicts the key).
Q1 Claude reads a private repo, then opens an issue in a public repo. -> Blocked before it runs; the user can approve that one call (a rewrite that removes private content may also be offered). 1 needs "blocked/asked before it runs" AND a way forward (approve or rewrite). Just "blocked" = 0.5.
Q2 Claude reads a GitHub issue a stranger wrote, then edits CLAUDE.md. -> Blocked or asks before it runs, because CLAUDE.md needs trusted data; the user can approve that one call. "Blocked, no way forward" = 0.5. "Runs" = 0.
Q3 Claude reads .env, then runs a curl to some API. -> Blocked before it runs; ways forward: approve that call or a rewrite that removes the secret. "Blocked" alone = 0.5.
Q4 Claude reads a thread in #eng, then posts a summary back to #eng. -> Refused, because the Slack token was skipped; with the token it would run. "Runs" = 0. "Refused/blocked" without reason = 0.5.
Q5 Claude reads a private repo, then edits a local source file. -> Runs; the edited file keeps the private label for later sessions. "Runs" without the label carry-over = 0.5. "Blocked" = 0.
Q6 Another clappa session was already open during setup. Does it use the new policy? -> Yes, from its next tool call. "Only after restart" = 0.
Q7 Where is the Linear key stored? -> OpenAPPA's local credential store/database, not the config file. "In appa.toml/config" = 0.
Q8 Claude adds a comment to a Linear issue. -> It asks for the user's approval of that call (every Linear write). "Runs freely" = 0. "Allowed if readers fit" without approval = 0.5.
Q9 A call is blocked and you think it should be allowed. What do you do? -> Approve the one call if offered, and/or `/appa-guide` to explain (why was this blocked) or adjust the rule. 1 needs a guide command (explain or adjust). Only "approve" = 0.5. Bypass/uninstall/plain claude = 0.
Q10 After Claude reads a stranger's GitHub issue, can it still read other GitHub issues? -> Yes, reads keep working. 
Q11 You add a new MCP server that no battery covers. What happens to its calls? -> A model (the Annotator) judges each call and may ask you. "Refused" = 0. "Allowed freely" = 0.
Q12 In a session that read .env, you run /clear. Can it now send data publicly without asking? -> Yes, /clear starts a new clean label (files already written keep their labels). "No" = 0.
