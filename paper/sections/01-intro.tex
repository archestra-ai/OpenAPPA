\section{Introduction}\label{sec:intro}

An LLM agent with tools operates as a confused deputy in the textbook sense:
it acts with the authority of its principal while consuming data and
instructions across shared channels. Whenever an agent processes sensitive
context alongside unvetted tool outputs, external inputs, or untrusted data,
structural risks inevitably arise. Unauthorized data exfiltration, unintended
tool calls, and policy violations can result not only from adversarial prompt
injection---where attacker-controlled text hijacks control flow---but also from
model hallucinations, ambiguous instructions, or miscalibrated agent reasoning.
In all these cases, exposing a capable agent to private data, external sinks,
and unvetted content turns read access into a vector for exfiltration and policy
breaches.

Many deployed defenses cluster at two poles. At one pole, imperative
guardrails: prompt-injection classifiers, regex filters, and output hygiene.
These judge \emph{content}, so they are bypassed by paraphrase, offer no
guarantees against non-adversarial agent errors, and treat prompt injection as an
isolated bug rather than a symptom of mixed-confidentiality processing. At the
other pole, hard restriction: allowlists, human approval on every call,
no-tools-after-untrusted-read policies. These judge \emph{structure} but do so
statically and coarsely, taxing every benign action and destroying agent
utility.

Agent information-flow control (IFC) supplies a third point. CaMeL separates
control and data flow~\cite{camel2025}; Fides propagates confidentiality and
integrity labels through messages, actions, arguments, and results, then
checks consequential calls against deterministic policies~\cite{fides}. Fides
also identifies the utility problem central to this paper: letting a
restrictive result enter planner context can disable useful later calls. It
responds by selectively storing such results in labeled variables and
revealing constrained derivatives through a quarantined LLM. \appa{} builds
directly on this premise. It does not claim deterministic IFC enforcement or
selective hiding as new; it asks whether a restrictive read can be explored
without tainting the long-lived planner trajectory at all.

The fixed point first. \appa{}'s entire run state is two monoids. A
\textbf{label}---audience (a reader set) $\times$ trust (a rank in a finite
chain)---travels with the data and is \emph{checked}; tool contracts declare
label \emph{actions} (restrictive reads intersect and take minima---in v1 the
only action kind: rulings cover gaps check-transiently and never act on the
label), and the trajectory label is the composition of the actions of the
calls that actually dispatched. An append-only \textbf{event log} travels with
the run and is \emph{recorded, never approved}: world events (egress,
mutation) appended at dispatch, and governance events (rulings and the
dispatches that consume them, boundaries, sanitizer applications, casts).
Every policy decision is a label comparison or a log predicate, or a declared
per-call attention demand; anything imperative---approval, sanitization, ACL
resolution---lives in registered components outside the engine. With no
permissive action the fold is a bag of meets---commutative, monotone,
settling; the non-commutative algebra (a restricted read \emph{after} a
granted widening re-narrowing the state and evicting the added readers) moves
wholesale into the epoch-wide-raise extension---expressible, deliberately not
taken (\S\ref{sec:limitations}).

The central construction is \textbf{branching as taint prevention}. Classical
IFC prices release: reads are free, and the taint bill arrives at the sink.
\appa{} instead intercepts a prospective descent before the read and can fork
a child trajectory. The child inherits the parent's label---a fresh public
slate would be a laundering primitive---and only the child receives the
restrictive result. It can inspect that result and invoke further tools under
its descended label, while the parent remains exactly at its pre-fork label.
At exit, the branch is abandoned or returns one explicitly labeled value. A
raw return carries its restriction into the parent by meet; preserving the
parent therefore requires a predeclared sanitizer or a quarantine-exit
attestation that bounds the derivative. \appa{} never removes taint from an
already exposed trajectory. It prevents the exposure and confines any
resulting descent to a disposable child.

This construction turns acquisition itself into a policy event. \appa{} orders
label states by restrictiveness and soft-blocks any call whose prospective
state strictly descends. The resulting plans make the choice explicit: accept
the narrowing in the current trajectory, fork and confine it, apply a
registered sanitizer, or decline the read. Because raise-free steps only
descend and every remedy is statically declared, the remedy space is finite
and enumerable from the registry. An empty set is therefore a proof that no
registered release-side remedy exists rather than a search timeout.
(Acquisition blocks are not empty: accepting the descent is always available
and branching is available in confining deployments.)

Two rules keep branches from becoming laundering or history-erasure
primitives. First, fork copies the parent's current label and merge absorbs
the returned value by intersection/minimum, so a child cannot widen its parent
by returning mislabeled raw data. Second, all branches append world events to
one shared log in real time: an egress that happened in a child happened in
the world, even if the child is later abandoned. These are the two senses in
which branching prevents trajectory taint without pretending the branch never
existed.

Atomic, call-scoped judgment supports the construction where discretionary
release is necessary. The engine renders a pending call (tool plus resolved
arguments and provenance, never the agent's paraphrase), puts that exact
call to an authority, and on approval dispatches it in the same
indivisible step. Approval and dispatch coincide, so no grant object exists to
steal, replay, or misbind; the ruling covers one dispatch while the label
stays put. Together with remedy-set soundness---every offered plan is
individually sound, so which plan a possibly tainted agent selects is
security-irrelevant---this gives the branch exit an agentic
robust-declassification discipline~\cite{zdancewic2001robust}.

Contributions, in order of importance:
\begin{enumerate}
  \item \textbf{Branching as taint prevention:} fork-before-read semantics
    that confine restrictive observations to a child, preserve the parent
    before merge, permit only policy-bounded exits, and retain honest world
    history in a shared log (\S\ref{sec:branching}).
  \item A prospective acquisition check that exposes acceptance, branching,
    sanitization, and refusal as sound plans before restrictive data enters a
    trajectory, with plans finitely enumerable from the registry
    (\S\ref{sec:enforcement}).
  \item A two-monoid model supporting the construction---label actions
    checked, events recorded---with policy as pure data and proofs of monotone
    descent, parent preservation, and merge confinement (\S\ref{sec:model}).
  \item Atomic, call-scoped rulings over engine-rendered requests, used for
    bounded branch exits and other exceptional dispatches without ambient
    elevation or label widening (\S\ref{sec:rulings}).
  \item An open-source implementation---a pure decision core under a
    state-owning shell---evaluated on
    AgentDojo~\cite{debenedettiAgentDojoDynamicEnvironment2024} and compared
    directly with Fides (\S\ref{sec:implementation}--\S\ref{sec:evaluation}).

\end{enumerate}
