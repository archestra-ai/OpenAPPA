\section{Introduction}\label{sec:intro}

Delegating tasks to an LLM agent introduces a computational variant of the principal--agent problem~\cite{jensen1976theory,ross1973economic}: the agent acts with the delegated authority of its principal while consuming data and instructions across shared channels. Whenever an agent processes sensitive context alongside unvetted tool outputs, external inputs, or untrusted data, structural risks inevitably arise. Unauthorized data exfiltration, unintended tool calls, and policy violations can result from adversarial prompt injection---where attacker-controlled text hijacks control flow~\cite{greshake2023not}---but also from model hallucinations, ambiguous instructions, or miscalibrated agent reasoning~\cite{ji2023survey}. In all these cases, exposing a capable agent to private data, external sinks, and unvetted content turns read access into a vector for exfiltration and policy breaches.

Existing defenses generally fall into two main paradigms. On one hand, imperative guardrails---such as hardcoded conditional logic (\texttt{if} statements), prompt-injection classifiers, and output hygiene rules~\cite{inan2023llama,nvidia2023nemoguardrails}---judge content or enforce ad-hoc per-tool conditions. Such guardrails enumerate interactions rather than compose them: every new tool or policy rule requires revisiting ad-hoc conditional logic across the system. Content-judging guardrails are further bypassed by paraphrasing, offer no guarantees against non-adversarial agent errors, and treat prompt injection as an isolated bug rather than a symptom of mixed-confidentiality processing~\cite{sabelfeld2003language}. On the other hand, static structural restrictions---such as fixed allowlists, rigid role boundaries, or mandatory human-in-the-loop approvals---judge \emph{structure}. While deterministic, coarse structural restrictions tend to be overeager, severely degrading agent utility and blocking legitimate workflows~\cite{Liu2026SafeHarbor,Wang2025AgentSpec,Wei2026From}.

Agent Information-Flow Control (IFC) offers a principled third approach by tracking confidentiality and integrity labels across the agent's tools to track and restrict information flow between given sources and sinks~\cite{camel2025,fides}. However, existing agent IFC frameworks face a severe usability bottleneck: \emph{label creep}. When an agent reads restricted data, dynamic label tracking and taint tracking~\cite{clause2007dytan,bell2014phosphor,schwartz2010all} permanently elevate the context's confidentiality level, revoking access to downstream tools for the remainder of the task and degrading agent utility. \appa{} (\textbf{Agentic Permissions Policy Algebra}) resolves this usability bottleneck through twin core mechanisms: \emph{branching for taint confinement} and \emph{prospective acquisition enforcement with remedy plans}.

First, \appa{} operationalizes \emph{branching for taint confinement} to prevent label creep in the primary execution context. Instead of allowing a sensitive read to permanently pollute the main agent context and lock out downstream tools, \appa{} isolates sensitive computations within disposable child branches. Operating under narrowed permissions, the child branch inspects data or performs intermediate reasoning locally; upon exit, only clean sanitized derivatives or explicitly accepted returns reach the parent, leaving the primary context unpolluted and fully operational (Figure~\ref{fig:concept}).

Second, \appa{} introduces \emph{prospective acquisition enforcement} to turn data access blocks into structured, manageable policy events through \emph{remedy plans}. Rather than silently failing or forcing developers to scatter ad-hoc guardrails throughout agent code, \appa{} evaluates policy constraints prior to tool execution. When a prospective tool call would narrow permissions or trigger a policy violation, the engine generates actionable remedy plans---such as authority-mediated release, domain sanitization, or execution redispatch---resolving access bottlenecks through explicit, auditable governance rulings without persistent privilege creep.

Our contributions are as follows:
\begin{itemize}
  \item \textbf{Engine-managed branching for taint confinement:} label-seeded branching with branch-local Label folding, checked child returns, direct-parent merge, and tree-wide committed-effect tracking (\S\ref{sec:branching}).
  \item \textbf{Prospective acquisition enforcement:} a pre-read check on prospective Label descents, exposing structured remedy plans (\texttt{Authorize}, \texttt{Accept}), separately checked \texttt{Redispatch} recommendations, and refusal (\S\ref{sec:enforcement}).
  \item \textbf{Formal two-monoid policy model:} proving parent preservation and merge confinement over checked label actions and logged events (\S\ref{sec:model}).
  \item \textbf{Atomic authority rulings:} single-call rulings over engine-rendered requests, enabling bounded branch exits and exceptional dispatches without persistent privilege escalation (\S\ref{sec:rulings}).
  \item \textbf{Empirical evaluation:} a multi-turn benchmark across four models demonstrating that \appa{} suppresses exfiltration (0\%--7\% ASR) while branching recovers much of the utility taint tracking forfeits on three of four models (\S\ref{sec:evaluation}).
\end{itemize}
