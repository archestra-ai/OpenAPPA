\paragraph{Closest comparison: \textsc{Fides}.}
\textsc{Fides} is the main antecedent for \appa{}, formalizing dynamic information-flow control (IFC) for agent planners~\cite{fides}. While both systems share the core premise of structural, label-based enforcement decoupled from the LLM, they differ fundamentally in scope and timing. \textsc{Fides} mitigates label creep by evaluating tool outputs post-execution and selectively hiding restrictive fields in planner variables. In contrast, \appa{} operates at the trajectory level: prospective policy checks prevent restrictive acquisitions on the active path, while host-managed child branches isolate sensitive sub-computations under inherited label states. Furthermore, whereas \textsc{Fides}'s policy model permits confidentiality gaps when calls originate from high-integrity contexts~\cite{fides}, \appa{} manages discretionary exceptions via atomic authorization rulings over explicitly rendered tool calls while preserving underlying labels.

\paragraph{Semantic, memory, and provenance systems.}
As summarized in Table~\ref{tab:systems}, related frameworks address distinct operational scopes. NeuroTaint~\cite{caiGhostAgentRedefining2026} performs post-hoc causal analysis to reconstruct source-to-sink provenance offline across sessions, serving as a complementary auditor for semantic propagation. MemLineage~\cite{ouyangMemLineageLineageGuidedEnforcement2026} gates sensitive actions on signed memory entry derivation graphs across sessions. In contrast, \appa{}'s trajectory labels and append-only event log govern single execution runs, allowing MemLineage to provide persistent provenance at \appa{}'s boundary. Execution provenance taxonomies~\cite{wangAgentTracesTrust2026} model typed execution graphs; \appa{} captures the procedural subset via its append-only event log for auditing and policy checks without inferring claim-support dependencies. Benchmarks like AgentDojo~\cite{debenedettiAgentDojoDynamicEnvironment2024} provide injection suites for evaluation, whereas post-hoc benchmarks like TaintBench focus on detection rather than online prevention.

\paragraph{Theoretical foundations.}
\appa{} builds on foundational information-flow control (IFC) principles, including lattice models~\cite{denning1976lattice}, noninterference~\cite{goguen1982security}, least privilege~\cite{saltzer1975protection}, decentralized reader sets~\cite{myers1997dlm}, and robust declassification~\cite{sabelfeld2009declassification,zdancewic2001robust}. Its state dimensions draw structure from graded monads~\cite{katsumata2014graded}, authorization rulings act as single-use linear resources~\cite{wadler1990linear}, and unclassified types (\emph{Unknown}) follow gradual information-flow typing~\cite{disney2011gradual,fennell2013gradual} akin to type narrowing in partially annotated Python or TypeScript.


\paragraph{Agent security and structural isolation.}
Architecture patterns such as Dual LLMs~\cite{willison2023dual} and CaMeL~\cite{camel2025} establish structural isolation and prompt sandboxing for agent security. While context branching and sub-agent delegation are standard patterns in multi-agent frameworks and tree-search architectures, \appa{} formalizes branching as a dynamic information-flow control primitive, governing child context setup through label inheritance ($L_p^{\mathrm{fork}}$), local label folding, and audited merge exits. However, CaMeL requires fully reworking the execution harness to enforce rigid control-data pipelines and multi-role agent orchestrations. In contrast, \appa{} integrates with standard agent harnesses through pre-dispatch interceptor hooks and host-managed session interfaces, isolating restrictive sub-computations without altering the core planner loop. Imperative guardrails and prompt filters focus primarily on content filtering~\cite{inan2023llama,zou2023universal}, whereas concerns regarding approval fatigue in human-in-the-loop systems~\cite{akhawe2013alice} motivate \appa{}'s automated candidate plan generation.

\paragraph{Capability-safe programming language harnesses.}
Language-based security abstractions have recently been applied to agent safety harnesses. Odersky et al.~\cite{odersky2026tracking} propose TACIT, which embeds agents in a capability-safe harness using Scala~3 with capture checking. By requiring agents to express intentions as executable code and statically tracking capabilities via the compiler, TACIT enforces local purity (side-effect-free sub-computations) to prevent information leakage during classified data processing. However, capability-safe code generation requires agents to emit syntactically and semantically valid Scala~3 code, restricting the interaction paradigm to specific compiled language environments and code generation workloads. In contrast, \appa{} operates dynamically at the tool-dispatch layer of standard agent harnesses. By combining prospective label descent with host-established child trajectories, \appa{} achieves trajectory-level taint confinement across standard tool-calling LLMs and protocol gateways (such as MCP~\cite{mcp2024spec}) without requiring code synthesis or compiler-level type checking.
