\section{Related Work}\label{sec:related}

\paragraph{Closest comparison: Fides.}
Fides is the main antecedent for \appa{}. It formalizes dynamic information-flow control (IFC) for agent planners, tracking confidentiality and integrity labels across planner state and tool interactions to enforce deterministic trusted-action and permitted-flow policies~\cite{fides}. To prevent label creep from over-restricting the planner context, Fides selectively hides restrictive result fields in labeled variables, exposing bounded derivatives through a quarantined LLM. \appa{} shares the core premise that security enforcement should be structural, label-based, and decoupled from the LLM. However, its primary distinction lies in using \emph{trajectories} rather than individual variables as the unit of taint containment: prospective policy checks prevent restrictive acquisitions on the active trajectory, while host-established child branches isolate sensitive sub-computations under the inherited label state.

The primary point of comparison between the two systems is how they mitigate label creep. Fides evaluates tool outputs post-execution to decide whether to restrict fields in the main planner context. In contrast, \appa{} performs prospective checks prior to tool dispatch. When an acquisition would narrow the active trajectory's label, \appa{} blocks dispatch and presents candidates for in-session acceptance or authorized release, while supporting explicit host-managed child trajectories to isolate reads without contaminating the parent context.
A child branch inherits the parent label, exit conditions undergo explicit merge checks, and the real-world execution log remains shared. Furthermore, while Fides's policy model permits potential confidentiality gaps when calls originate from high-integrity contexts~\cite{fides}, \appa{} models discretionary exceptions through atomic authorization rulings over explicitly rendered tool calls while preserving underlying labels. The primary contribution of \appa{} lies in its branching-based taint confinement mechanism and its associated fork, exit, and shared-history invariants, rather than in deterministic IFC itself. \paragraph{Semantic and causal taint.}
NeuroTaint reconstructs source-to-sink provenance offline from execution traces using semantic evidence, causal analysis, and persistent context to detect implicit or cross-session influence~\cite{caiGhostAgentRedefining2026}. Its evaluation highlights a fundamental limitation of traditional label-based systems: declared labels do not automatically capture whether a subsequent text generation or control flow decision was causally derived from a sensitive source. \appa{} does not attempt to solve post-hoc semantic causality analysis; instead, it operates as an online enforcement mechanism over declared contracts and policy resolvers, whereas NeuroTaint serves as a complementary auditor to verify whether runtime flows match semantic execution patterns.

\paragraph{Persistent memory lineage.}
MemLineage signs memory entries, constructs an LLM-mediated derivation graph, propagates untrusted ancestry across sessions, and gates sensitive actions on active justifications~\cite{ouyangMemLineageLineageGuidedEnforcement2026}. In contrast, \appa{}'s trajectory labels and event log govern individual execution runs. While its append-only log ensures replayability and auditability, \appa{} does not track lineage across memory entries or persist taint across sessions. Thus, the two systems are complementary: MemLineage can provide persistent provenance at the boundary of \appa{}'s execution context.

\paragraph{Execution provenance.}
The provenance taxonomy by Wang et al.\ categorizes typed execution graphs, runtime enforcement, tool-use provenance, and memory lineage~\cite{wangAgentTracesTrust2026}. \appa{}'s append-only event log models the procedural subset of this taxonomy: it records dispatch and governance history for policy evaluation and auditing without inferring claim-support dependencies or semantic influence.

\paragraph{Security and prompt-injection benchmarks.}
AgentDojo provides realistic user tasks, injection benchmarks, tool suites, and an extensible defense framework~\cite{debenedettiAgentDojoDynamicEnvironment2024}. It serves as both the evaluation environment for \appa{} and the foundation for comparative evaluation against Fides. Benchmarks like TaintBench focus on post-hoc propagation detection~\cite{caiGhostAgentRedefining2026}, addressing a distinct problem from real-time policy enforcement.

\paragraph{Theoretical foundations.}
\appa{} inherits foundational information-flow control (IFC) principles, including lattice models~\cite{denning1976lattice}, noninterference semantics~\cite{goguen1982security}, least privilege at the trajectory level~\cite{saltzer1975protection}, and decentralized label reader sets~\cite{myers1997dlm}. Its sanitization and endorsement mechanisms mirror the dimensions of robust declassification~\cite{sabelfeld2009declassification,zdancewic2001robust}. The underlying state dimensions draw structure from graded monads~\cite{katsumata2014graded}, authorization rulings act as single-use resources following linear logic principles~\cite{wadler1990linear}, and unclassified types (\emph{Unknown}) are treated via gradual information-flow typing~\cite{disney2011gradual,fennell2013gradual} akin to type narrowing in partially annotated Python (\texttt{mypy}) or TypeScript.


\paragraph{Agent security and structural isolation.}
Architecture patterns such as Dual LLMs~\cite{willison2023dual} and CaMeL~\cite{camel2025} establish structural isolation and prompt sandboxing for agent security. A key practical limitation of CaMeL and related structural approaches is that they require fully reworking the execution harness to enforce advance planning, multi-role agent decomposition, and custom control-data pipelines. In contrast, \appa{} integrates with standard execution harnesses by requiring the host application to explicitly establish and drive child sessions when executing isolated trajectories, alongside tool dispatch hooks for policy checks and sanitizer execution. By combining prospective label checks with formal fork, exit, and shared-history invariants for host-driven child trajectories, \appa{} prevents taint accumulation in the main execution path while remaining embeddable in standard real-world agent deployments without altering the core planner. Imperative guardrails and prompt filters focus primarily on content filtering~\cite{inan2023llama,zou2023universal}, whereas concerns regarding approval fatigue in human-in-the-loop systems~\cite{akhawe2013alice} motivate \appa{}'s automated candidate plan generation.

\paragraph{Capability-safe programming language harnesses.}
Language-based security abstractions have recently been applied to agent safety harnesses. Odersky et al.~\cite{odersky2026tracking} propose TACIT, which embeds agents in a capability-safe harness using Scala~3 with capture checking. By requiring agents to express intentions as executable code and statically tracking capabilities via the compiler, TACIT enforces local purity (side-effect-free sub-computations) to prevent information leakage during classified data processing. However, capability-safe code generation requires agents to emit syntactically and semantically valid Scala~3 code, restricting the interaction paradigm to specific compiled language environments and code generation workloads. In contrast, \appa{} operates dynamically at the tool-dispatch layer of standard agent harnesses. By combining prospective label descent with host-established child trajectories, \appa{} achieves trajectory-level taint confinement across standard tool-calling LLMs and protocol gateways (such as MCP~\cite{mcp2024spec}) without requiring code synthesis or compiler-level type checking.
