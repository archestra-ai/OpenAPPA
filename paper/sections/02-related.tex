\paragraph{Closest comparison: \textsc{Fides} and Agent IFC.}
\textsc{Fides} is the primary antecedent for \appa{}, formalizing dynamic information-flow control (IFC) for agent planners~\cite{fides}. While both systems share the core premise of structural, label-based enforcement decoupled from the LLM, they differ fundamentally in scope and timing. Other structural frameworks, such as ACE~\cite{li2026ace}, decouple planning into abstract and concrete phases to enforce information flow via static plan verification before execution. \textsc{Fides} mitigates label creep by evaluating tool outputs post-execution and selectively hiding restrictive fields in planner variables. In contrast, \appa{} operates dynamically at the trajectory level: prospective policy checks prevent restrictive acquisitions on the active path, while host-managed child branches isolate sensitive sub-computations under inherited label states. Furthermore, whereas \textsc{Fides}'s policy model permits confidentiality gaps when calls originate from high-integrity contexts~\cite{fides}, \appa{} manages discretionary exceptions via atomic authorization rulings over explicitly rendered tool calls while preserving underlying labels.

\paragraph{Semantic, memory, and provenance systems.}
As summarized in Table~\ref{tab:systems}, related frameworks address distinct operational scopes. NeuroTaint~\cite{caiGhostAgentRedefining2026} performs post-hoc causal analysis to reconstruct source-to-sink provenance offline across sessions, serving as a complementary auditor for semantic propagation. MemLineage~\cite{ouyangMemLineageLineageGuidedEnforcement2026} gates sensitive actions on signed memory entry derivation graphs across sessions. In contrast, \appa{}'s trajectory labels and append-only event log govern single execution runs, allowing MemLineage to provide persistent provenance at \appa{}'s boundary. Execution provenance taxonomies~\cite{wangAgentTracesTrust2026} model typed execution graphs; \appa{} captures the procedural subset via its append-only event log for auditing and policy checks without inferring claim-support dependencies. Evaluation suites like AgentDojo~\cite{debenedettiAgentDojoDynamicEnvironment2024}, InjecAgent~\cite{deng2024injecagent}, and ToolEmu~\cite{ruan2024identifying} benchmark adversarial prompt injection and tool misuse scenarios, whereas post-hoc benchmarks like TaintBench focus on detection rather than online prevention.

\paragraph{Operating systems dynamic IFC and process isolation.}
Classical operating system dynamic IFC frameworks—such as Flume~\cite{krohn2007information}, HiStar~\cite{zeldovich2006making}, and Asbestos~\cite{efstathopoulos2005labels}—introduced process-level label propagation and dynamic isolation under process creation (\texttt{fork}). \appa{} translates these OS-level dynamic IFC primitives to autonomous agent execution trajectories. Modern container and browser sandboxing runtimes—such as DeltaBox~\cite{dong2026deltabox}, Crab~\cite{wu2026crab}, and ceLLMate~\cite{meng2025cellmate}—provide OS-level checkpoint/restore and HTTP-layer authority sandboxing for agent environments. \appa{} operates orthogonally: while system sandboxes snapshot OS processes and filesystem layers, \appa{} establishes host-managed context branching with label inheritance ($L_c^0 := L_p^{\mathrm{fork}}$) and transcript isolation. This ensures that unvetted tool data acquired during sub-task execution narrows permissions only within the child branch, keeping the parent trajectory untainted without relying on retroactive memory rollback or hardware enclaves.

\paragraph{Agent reasoning architectures vs.\ security branching.}
Context branching and tree-structured exploration are standard patterns in LLM reasoning frameworks, including Tree of Thoughts~\cite{yao2023tree}, Language Agent Tree Search (LATS)~\cite{zhou2024language}, multi-agent systems like AutoGen~\cite{wu2023autogen}, and Branching Policy Optimization (BPO)~\cite{he2026bpo} for RL rollout variance reduction. While these architectures employ context branching to optimize problem-solving trajectories, evaluate candidate action branches, or improve sample efficiency, \appa{} repurposes context branching as a security-critical dynamic IFC primitive. Rather than exploring execution paths for utility optimization, \appa{}'s context branching enforces label containment ($L_p^{\mathrm{preservation}}$), governing child context initialization, local label folding, and audited merge exits to isolate sensitive sub-computations.

\paragraph{Imperative guardrails and structural isolation.}
Imperative guardrails and runtime toolkits—such as NeMo Guardrails~\cite{nvidia2023nemoguardrails}, Llama Guard~\cite{inan2023llama}, and adversarial prompt classifiers~\cite{zou2023universal}—primarily enforce content filtering and pattern matching. However, content filters do not track state lineage and remain vulnerable to paraphrasing or multi-turn context drift. Architectural patterns such as Dual LLMs~\cite{willison2023dual} and CaMeL~\cite{camel2025} establish structural isolation and prompt sandboxing. However, CaMeL requires fully reworking the execution harness to enforce rigid control-data pipelines and multi-role agent orchestrations. In contrast, \appa{} integrates with standard agent harnesses through pre-dispatch interceptor hooks and host-managed session interfaces to enforce prospective lattice checks. Concerns regarding approval fatigue in human-in-the-loop systems~\cite{akhawe2013alice} motivate \appa{}'s single-call atomic authorization rulings.

\paragraph{Theoretical foundations and capability-safe harnesses.}
\appa{} builds on foundational information-flow control (IFC) principles, including lattice models~\cite{denning1976lattice}, noninterference~\cite{goguen1982security}, least privilege~\cite{saltzer1975protection}, decentralized reader sets~\cite{myers1997dlm}, dynamic taint analysis~\cite{clause2007dytan,bell2014phosphor,schwartz2010all}, and robust declassification~\cite{sabelfeld2009declassification,zdancewic2001robust}. Its state dimensions draw structure from graded monads~\cite{katsumata2014graded}, authorization rulings act as single-use linear resources~\cite{wadler1990linear}, and unclassified types (\emph{Unknown}) follow gradual information-flow typing~\cite{disney2011gradual,fennell2013gradual}.
Recently, capability-safe programming language harnesses have been applied to agent safety. TACIT~\cite{odersky2026tracking} embeds agents in a capability-safe harness using Scala~3 with capture checking, static capability tracking, and local purity. However, TACIT requires agents to synthesize syntactically and semantically valid Scala~3 code. In contrast, \appa{} operates dynamically at the tool-dispatch layer of standard agent harnesses and protocol gateways (such as MCP~\cite{mcp2024spec}, SMCP~\cite{hou2026smcp}, and MCPShield~\cite{zhou2026mcpshield}) without requiring code synthesis or compiler-level type checking.
