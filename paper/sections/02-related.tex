\section{Related Work}\label{sec:related}

\paragraph{Closest comparison: Fides.}
Fides is the main antecedent for \appa{}. It formalizes dynamic information-flow control (IFC) for agent planners, tracking confidentiality and integrity labels across planner state and tool interactions to enforce deterministic trusted-action and permitted-flow policies~\cite{fides}. To prevent label creep from over-restricting the planner context, Fides selectively hides restrictive result fields in labeled variables, exposing bounded derivatives through a quarantined LLM. \appa{} shares the core premise that security enforcement should be structural, label-based, and decoupled from the LLM. However, its primary distinction lies in using disposable \emph{trajectories} rather than individual variables as the unit of taint containment: a restrictive call and its dependent reasoning occur within a child branch governed by the descended label.

The primary point of comparison between the two systems is how they mitigate label creep. Fides evaluates tool outputs post-execution to decide whether to restrict fields in the main planner context. In contrast, \appa{} evaluates policies prior to tool dispatch, offering four distinct strategies: accepting taint on the active trajectory, forking a child trajectory to isolate the read, returning a registered derivative value, or declining the execution. A child branch inherits the parent label, exit conditions undergo explicit merge checks, and the real-world execution log remains shared. Furthermore, while Fides's policy model permits potential confidentiality gaps when calls originate from high-integrity contexts~\cite{fides}, \appa{} models discretionary exceptions through atomic authorization rulings over explicitly rendered tool calls while preserving underlying labels. The primary contribution of \appa{} lies in its branching-as-taint-prevention mechanism and its associated fork, exit, and shared-history invariants, rather than in deterministic IFC itself. \paragraph{Semantic and causal taint.}
NeuroTaint reconstructs source-to-sink provenance offline from execution traces using semantic evidence, causal analysis, and persistent context to detect implicit or cross-session influence~\cite{caiGhostAgentRedefining2026}. Its evaluation highlights a fundamental limitation of traditional label-based systems: declared labels do not automatically capture whether a subsequent text generation or control flow decision was causally derived from a sensitive source. \appa{} does not attempt to solve post-hoc semantic causality analysis; instead, it operates as an online enforcement mechanism over declared contracts and policy resolvers, whereas NeuroTaint serves as a complementary auditor to verify whether runtime flows match semantic execution patterns.

\paragraph{Persistent memory lineage.}
MemLineage signs memory entries, constructs an LLM-mediated derivation graph, propagates untrusted ancestry across sessions, and gates sensitive actions on active justifications~\cite{ouyangMemLineageLineageGuidedEnforcement2026}. In contrast, \appa{}'s trajectory labels and event log govern individual execution runs. While its append-only log ensures replayability and auditability, \appa{} does not track lineage across memory entries or persist taint across sessions. Thus, the two systems are complementary: MemLineage can provide persistent provenance at the boundary of \appa{}'s execution context.

\paragraph{Execution provenance.}
The provenance taxonomy by Wang et al.\ categorizes typed execution graphs, runtime enforcement, tool-use provenance, and memory lineage~\cite{wangAgentTracesTrust2026}. \appa{}'s append-only event log models the procedural subset of this taxonomy: it records dispatch and governance history for policy evaluation and auditing without inferring claim-support dependencies or semantic influence.

\paragraph{Security and prompt-injection benchmarks.}
AgentDojo provides realistic user tasks, injection benchmarks, tool suites, and an extensible defense framework~\cite{debenedettiAgentDojoDynamicEnvironment2024}. It serves as both the evaluation environment for \appa{} and the foundation for comparative evaluation against Fides. Benchmarks like TaintBench focus on post-hoc propagation detection~\cite{caiGhostAgentRedefining2026}, addressing a distinct problem from real-time policy enforcement.

\paragraph{Classical IFC.}
Lattice models~\cite{denning1976lattice} and noninterference semantics~\cite{goguen1982security} establish the information-flow principles inherited by \appa{}. In agentic environments, long-lived planner contexts are vulnerable to label creep, which can permanently degrade agent capabilities~\cite{fides,sabelfeld2003language}. Performing a fork prior to a restrictive read transforms data acquisition into an isolation step, avoiding irreversible restriction of the main planner context.

\paragraph{Decentralized labels and reader sets.}
Structuring audiences as reader sets draws from the decentralized label model~\cite{myers1997dlm}, where security rulings symbolically bind principal groups and resolve membership dynamically during policy evaluation.

\paragraph{Declassification.}
The dimensions of declassification outlined by Sabelfeld and Sands~\cite{sabelfeld2009declassification} correspond to \appa{}'s sanitization (what) and approval/endorsement (who) mechanisms. The ruling discipline targets robust declassification~\cite{zdancewic2001robust}, adapted to agentic execution flows (\S\ref{sec:rulings}).

\paragraph{Least privilege.}
\appa{}'s state-acquisition check applies the principle of least privilege~\cite{saltzer1975protection} at the trajectory level.

\paragraph{Graded and parametric effect structure.}
The state dimension interface (carrier, ordered action monoid, and adequacy relation) is structured after graded monads~\cite{katsumata2014graded}. However, this interface is deliberately excluded from runtime extension: while policy folds can be property-tested, the security semantics of new dimensions require static engineering review rather than dynamic registration.

\paragraph{Gradual typing for security.}
Following gradual information-flow typing~\cite{disney2011gradual,fennell2013gradual}, unclassified types (\emph{Unknown}) are treated as unadmitted states rather than lattice elements, and boundary casts handle unclassified inputs explicitly.

\paragraph{Linearity.}
In \appa{}, rulings function as single-use resources in line with linear logic principles~\cite{wadler1990linear}: an authorization ruling is consumed immediately upon the dispatch of its corresponding action (\S\ref{sec:rulings}).

\paragraph{Agent security.}
Architecture patterns such as Dual LLMs~\cite{willison2023dual} and CaMeL~\cite{camel2025} establish structural isolation and prompt sandboxing for agent security, while formal language abstractions for security appear in~\cite{adts2026}. \appa{} specifically links isolation to prospective label descent, defining formal fork, exit, and shared-history semantics. This ensures branching prevents taint accumulation in the main execution path rather than merely separating model roles. Imperative guardrails and prompt filters focus primarily on content filtering~\cite{inan2023llama,zou2023universal}, whereas concerns regarding approval fatigue in human-in-the-loop systems~\cite{akhawe2013alice} motivate \appa{}'s automated candidate plan generation.
