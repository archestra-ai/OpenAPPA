\section{The Model}\label{sec:model}

\paragraph{Label state.}
The label state is $S = \powerset(U) \times T$, where the first component is a reader set over a finite universe $U$ and the second is a trust rank in a finite chain $T$. Readers may be named, nested groups; these groups are symbolic and closed under $\cap$ and $\cup$, while configured containments are data rather than code. Registered resolvers determine raw-identifier membership afresh at each check. Thus, removing a member excludes it from all subsequent checks without retroactively altering prior decisions. The trust-chain instance is deployment-configurable. Power sets and finite chains satisfy the monoid and lattice axioms by construction~\cite{denning1976lattice,birkhoff1967lattice}, preserving algebraic correctness without requiring custom proof obligations from deployers.

\paragraph{Checked actions.}
The checked monoid models policy actions on $S$, equipped with action composition and identity. In the primary model, non-identity actions are strictly restrictive meets:
\[
  a_i = (\cap A_i, \min r_i).
\]
Rulings resolve execution policy requirements per call without modifying the label state directly. Because label aggregation ($\fold$) composes meets, it is commutative and monotone. The expressible extension (\S\ref{sec:limitations}) introduces permissive actions $(\cup B, \max r)$ up to a declared ceiling, rendering the fold non-commutative.

\begin{proposition}[Collapse]\label{prop:collapse}
In the primary model, the fold collapses to a running meet consisting of a single reader set intersection and a minimum trust level, eliminating the need to re-evaluate trajectory history. Under the permissive extension, every composite audience action simplifies to the form $s \mapsto (s \cap A) \cup B$, representing a cumulative intersection-union pair over individual actions.
\end{proposition}
Proof in Appendix~\ref{app:proofs}.

\begin{proposition}[Monotone descent and settlement]\label{prop:descent}
In the primary model, every label update is a meet operation. Because both underlying sets are finite, the label state descends monotonically under the partial order and stabilizes after finitely many strict descents.
\end{proposition}
Note that label stabilization reflects bounded permission narrowing rather than execution termination, as identity actions may continue indefinitely. Proof in Appendix~\ref{app:proofs}.

\paragraph{Branch state.}
Labels are trajectory-local, whereas the event log is globally shared. A \texttt{fork(p)} operation creates a child trajectory with initial label $L_c := L_p$ and a pre-declared exit contract. Subsequent child actions fold exclusively into $L_c$. Parent and child nevertheless append to the same serialized event log. Prior to an explicit \texttt{submit\_result(v)} merge, no child context or result values enter the parent trajectory.

\begin{proposition}[Parent preservation]\label{prop:preservation}
For every child trace beginning at a fork, $L_c \le L_p^{\mathrm{fork}}$, and every child action leaves the parent's label unchanged. Trajectory abandonment therefore preserves the parent state exactly. A merge computes $L_p' = L_p \meet \lab(v)$, which cannot widen the parent label and preserves it exactly if and only if $L_p \le \lab(v)$.
\end{proposition}
\begin{definition}[Taint-preventing branch]
A branch is taint-preventing when it is abandoned or exits under the adequacy relation $L_p \le \lab(v)$.
\end{definition}
Returning an un-sanitized restrictive raw value maintains safety but propagates restrictions back to the parent trajectory, requiring re-evaluation against the prospective acquisition policy. Proof in Appendix~\ref{app:proofs} follows from locality of the child fold and the meet laws.

\paragraph{The log monoid.}
The log is modeled as the free monoid over events under concatenation~\cite{pierce2002types}, where events are appended at dispatch without separate approval phases. Events fall into two primary categories:
\begin{itemize}
  \item \textbf{World events} record external side-effects at dispatch time. History predicates evaluate over dispatch attempts: \texttt{no\_prior} operates fail-closed by recording execution attempts even on failure, while \texttt{prior(k)} verifies dispatch occurrence rather than completion.
  \item \textbf{Governance events} record rulings, associated dispatches, trajectory boundaries (turn ends, forks, merges), accepted label descents, sanitizer applications, and label casts.
\end{itemize}

The engine queries the log solely to evaluate history predicates, verify ruling validity, and perform audits. Cached projections, such as tracking observed event types, correspond to monoid homomorphisms~\cite{pierce2002types}. Separate ``effects dimensions'' used in prior architectures are represented directly as log projections rather than label components: an effect tracks execution history rather than data confidentiality and integrity. Unifying events and labels into a single monoid product would blur essential semantic distinctions between per-value policy bounds and per-run execution logs.

\paragraph{Integrating external policy logic through log views.}
Custom execution policies and numerical thresholds are implemented via log projections coupled with external authority resolvers. For example, cumulative metrics such as financial spend limits (\texttt{finance.spend}) are computed by log views that determine whether an action requires human authorization. Recording these operations as named log events avoids introducing quantitative state into the label algebra, keeping scalar magnitudes outside the lattice model.

\paragraph{Contracts.}
A tool contract specifies policy declarations for both monoids: a \texttt{delta} action evaluated against the label, and an \texttt{emits} sequence appended to the log upon dispatch. Contracts also specify \texttt{requires} clauses: minimum trust floors, audience cover constraints $\readers(\fold) \supseteq \mathrm{recipients}$, source context bounds ($\subseteq C$, optionally \texttt{strict}), history predicates (persistent-negative \texttt{no\_prior} and persistent-positive \texttt{prior}), and call-scoped attention requirements. Unlike historical event constraints, attention demands cannot be satisfied by past actions; they require an explicit ruling from an authorizing component during atomic plan execution. Routing \texttt{tags} convey no algebraic weight and serve solely to route requests to appropriate policy authorities (\S\ref{sec:rulings}).

Dynamic resolvers and variable placeholders belong to the trusted computing base. Surface conventions, such as automatic source deltas derived from access control lists, simplify policy specification without altering underlying contract semantics.

\paragraph{Unknown.}
Unknown values are not represented as elements within the lattice carrier; there is no ordering such as $\mathit{trusted} < \mathit{unknown} < \mathit{suspicious}$. Unresolved attributes remain outside the label algebra, preserving total algebraic composition and monoid laws while policy checks detect missing information. Reclassifying unknown inputs requires explicit, audited cast events. A cast is defined either as a static constant or via a dynamic resolver restricted to a bounded set of admissible target labels. Static casts establish a fixed default policy, while target ceilings prevent dynamic classifiers from arbitrarily elevating un-trusted data. This treatment aligns with gradual typing interpretations of unknown values \cite{disney2011gradual,fennell2013gradual}.
