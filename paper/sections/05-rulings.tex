\section{Atomic Rulings and Robust Declassification}\label{sec:rulings}

\paragraph{One judgment and one dispatch rule.}
Every judgment follows a single canonical form: authority $A$ authorizes engine-rendered call $C$. System vocabulary consists exclusively of mandates, rulings, and log records. A call is dispatched if and only if: (1)~rulings cover all failed or demanded predicates, (2)~each issuing authority's mandate permits the exception, and (3)~all rulings target the identical rendered call and are consumed atomically. Multi-party authorization policies (such as two-person control~\cite{saltzer1975protection}) collect multiple rulings for one call. A ruling permits dispatch despite an unsatisfied predicate but never modifies the execution trajectory directly; instead, tool return values update the trajectory Label via standard accumulation (\S\ref{sec:model}), and successful dispatches record declared side effects in the event log $\mathcal{E}$. No ruling bypasses the explicit agent acceptance required for narrowing (\S\ref{sec:enforcement}).

\paragraph{Atomic plan execution.}
For a plan requiring authorization on a blocked step, an indivisible operation renders the call, presents provenance to the authority, and dispatches upon approval. Plan identifier, ruling, and dispatch event are recorded atomically in the event log. Approval and dispatch coincide, collapsing multi-stage grant lifecycles (issuing, binding, consuming)~\cite{miller2003paradigm} into an atomic step that prevents call substitution, replay attacks~\cite{needham1978using}, and intermediate interception~\cite{wadler1990linear}.

\paragraph{Call-scoped release.}
A ruling applies strictly to a single dispatch without altering the trajectory label. Single-command scope isolation ensures an authorized exception cannot persistently relax labels for subsequent attacker-influenced calls~\cite{saltzer1975protection}.

\begin{theorem}[Call-scoped release]\label{thm:release}
In every trajectory: (i)~a call dispatches despite unmet requirements only by atomically consuming a dedicated, covering ruling over its exact rendered call, and no ruling is consumed by more than one dispatch; (ii)~ruling and acceptance events do not modify any trajectory Label or the committed-effect projection $\mathcal{E}$; hence (iii)~every dispatch with an unmet release-side Label requirement is matched to explicit rulings in the log, and an authorized override widens no later Label and confers no authorization on other dispatches.
\end{theorem}
Proof in Appendix~\ref{app:proofs}. Corollary~\ref{cor:export} extends the guarantee to child-value export: because labels stay attached to data through merges (Theorem~\ref{thm:branch}), a later parent release that fails to satisfy the child value's Label requirement requires its own fresh ruling.

\paragraph{Mandate typology.}
Authority is bound to declarative mandates: (1)~\textbf{Cover mandates} (permitting trust gaps or audience ceilings), (2)~\textbf{Named waivers} (exempting history predicates), and (3)~\textbf{Gate mandates} (satisfying hard gates). A single ruling may address both an unmet predicate and a hard gate, but cannot bypass narrowing acceptance. Misrouted checks evaluate against the exact rendered call.

\paragraph{Response-sink rule.}
No primary user ruling can authorize a predicate for a direct user response sink, irrespective of mandate privileges, preventing in-band self-approval vulnerabilities~\cite{saltzer1975protection}.

\paragraph{Canonical rulings and robust release.}
Authorities evaluate the engine's canonical representation of a tool call, eliminating semantic evasion vectors where a compromised model requests actions under misleading phrasing. Following established declassification models, sanitization regulates \emph{what} information is released, whereas rulings govern \emph{who} permits release~\cite{sabelfeld2009declassification,zdancewic2001robust}, establishing robust declassification over exact rendered calls.

\paragraph{Sanitizers.}
Registered sanitizers transform values according to authorized state transitions without altering execution trajectories~\cite{bhagwatkarIndirectPromptInjections2025,caiGhostAgentRedefining2026}. Sanitization adjusts audience scope exclusively and never elevates trust levels without an explicit ruling, cast, or exit transformation (\S\ref{sec:branching}).

\paragraph{User-assistant trust boundary.}
The root response is modeled as a sink whose recipient set is the authenticated root principal, and is adequate exactly when the current trajectory Label covers that principal. Mediating that sink is out of scope in this version; only the structural bar above is enforced. External outbound communications remain encapsulated within tool calls subject to policy validation.
