\section{Branching for Taint Confinement}\label{sec:branching}

\paragraph{Observation model.}
\appa{} prevents parent context degradation by confining restrictive descents to disposable child branches, respecting the non-reversibility of trajectory taint once data enters an LLM context~\cite{caiGhostAgentRedefining2026}. Delegating restrictive data acquisitions to a child branch isolates label descents locally, leaving the primary parent trajectory untainted without asserting that the child process itself is untainted.

\paragraph{Deployment requirement.}
Branching requires an execution environment capable of isolating context trajectories (e.g., an application harness or proxy gateway). While baseline label enforcement (\S\ref{sec:enforcement}) operates in standard gateways, features such as host-managed context branching and output sanitization rely on runtime context confinement.

\subsection{Host branching protocol}
\appa{} models branching as a host-managed protocol surrounding engine enforcement:
\begin{enumerate}
  \item the host decides to create a child context;
  \item the host identifies the active parent trajectory;
  \item the \appa{} engine records a fork boundary and seeds the child from the parent's current label;
  \item the host submits child-local work;
  \item the child's calls are independently evaluated by the engine; and
  \item any returned value crosses through the checked child-return and direct-parent merge path.
\end{enumerate}

\subsection{Fork by inheritance}
When creating a child trajectory, \appa{} combines security-critical label inheritance with transcript isolation:
\begin{itemize}
  \item \textbf{Label inheritance}: The child inherits the parent's current Label state at the fork point, setting $L_c^0 := L_p^{\mathrm{fork}}$.
  \item \textbf{Transcript isolation}: The child begins with a fresh, branch-local model transcript containing only the server-controlled system preamble and child-local facts; parent user turns, assistant reasoning, and prior tool results are not copied.
\end{itemize}

Preserving Label inheritance ($L_c^0 := L_p^{\mathrm{fork}}$) is security-essential: starting a fresh child context with an unconstrained initial label would establish a laundering path for sensitive information already reflected in the parent's Label---for instance, allowing internal context to be released to a public output. The \texttt{fork} boundary also invalidates pending rulings and plan executions, as these records are bound to specific invocations in the parent context and cannot be transferred to a child.

However, transcript isolation introduces an operational utility limitation. Because the child receives a fresh model context rather than a continuation of the parent's conversation, the host application must supply the child's task instructions and inputs explicitly. While conservative for confidentiality, this design requires host-level prompt construction and task orchestration.

\subsection{Descend locally}
Child-local work is dispatched within the child context, where all subsequent actions are enforced against the evolving child label $L_c$. Updates to $L_c$ affect only the child label and never update $L_p$. The parent process may pause or proceed concurrently, but it remains isolated from child messages and tool outputs until an explicit exit occurs. This isolation guarantees the pre-merge properties of Proposition~\ref{prop:preservation}, regardless of the child's internal behavior.

\subsection{Exit explicitly}
An execution branch yields one of three outcomes:
\begin{enumerate}
  \item an \texttt{abandon} signal;
  \item the return of a standard labeled value; or
  \item the application of a registered sanitizer or verified exit transformation that produces a derived value.
\end{enumerate}
In all cases, APPA validates the actual result label prior to committing the merge. If the raw result would restrict permissions, it triggers the acquisition check in the parent context. The parent may explicitly accept the label reduction or reject the \texttt{merge}; however, accepting lower permissions does not achieve taint confinement. A declared exit bound can be verified prior to execution to enable planning, though the actual result label remains authoritative.

\begin{theorem}[Branch taint confinement]\label{thm:branch}
Given an explicitly created child seeded from a parent state $L_p^{\mathrm{fork}}$, admitted child actions do not modify the parent label $L_p$. If the child branch is abandoned, child execution does not change the parent's label. If the child returns a value $v$, merging combines the parent label with the engine-derived return label:
\[
  L_p' = L_p \wedge \mathit{label}(v).
\]
Hence no child action can widen or silently degrade its parent's label, and an exit satisfying $L_p \le \mathit{label}(v)$ preserves the parent label exactly.
\end{theorem}

This result establishes the correctness of the branch lifecycle once invoked. It follows directly from trajectory-local label folding and the algebraic properties of the meet operator, holding independently of the child's prompt, execution plan, or behavior. Proof in Appendix~\ref{app:proofs}.

\paragraph{History is shared, not merged.}
The parent and child process append to a single, real-time serialized event log. Any effect committed by a successfully closed child dispatch remains visible family-wide after abandonment; context isolation cannot undo these actions nor clear them from future \texttt{no\_prior(egress)} policy checks~\cite{wangAgentTracesTrust2026}. A successful child egress therefore affects a parent's \texttt{no\_prior(egress)} check, whereas a failed or indeterminate child dispatch does not add committed effects to the shared projection. Forking and merging function as governance operations. A policy ruling granted to a child is consumed during its execution and does not grant authorization to the parent. Each branch terminates via return, failure, or abandonment, requiring no log reconciliation because physical event history is never branched.

\paragraph{Sanitized branch exits.}
Following the Dual-LLM and CaMeL architectures~\cite{willison2023dual,camel2025}, sanitized branch exits pair a predeclared \texttt{submit\_result} schema with registered transformation functions. Schema validation alone never relaxes label restrictions, as structural compliance does not guarantee safe provenance~\cite{sabelfeld2003language}. Maintaining a parent process's trust level may require a verified transformation assertion~\cite{zdancewic2001robust}—for example, asserting that ``the returned integer represents a version number from the specified source and contains no unparsed text''—rather than simple parsing. Registering such a transformation incorporates its claim into the trusted computing base; this transformation assertion represents APPA's sole exception for structured label promotion without an explicit policy ruling.
