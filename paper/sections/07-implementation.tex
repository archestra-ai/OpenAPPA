\section{Implementation}\label{sec:implementation}

\appa{} is implemented in two decoupled layers: an inner pure algebraic core that evaluates policy decisions deterministically over event log folds~\cite{schneider2000enforceable,wangAgentTracesTrust2026}, and an outer runtime that manages state persistence, context isolation, and dispatch hooks. State views (such as folded labels and pending plans) are passed homomorphically as log folds~\cite{pierce2002types}. The outer layer creates disposable child contexts, maintains trajectory isolation, and enforces return-label validation prior to merges.

\paragraph{Harness embeddability and session interface.}
Unlike frameworks requiring full harness rewrites~\cite{camel2025} or static capture checking~\cite{odersky2026tracking}, \appa{} embeds surgically into standard runtimes via pre-dispatch interceptor hooks and an explicit host interface for session management. Creating a child context requires passing an explicit parent-session reference to seed the isolated child trajectory from the active parent state, leaving child session creation strictly under host control.

The implementation distinguishes two separate mechanisms for handling policy decisions and state transitions: (1)~the \emph{ordinary narrowing path}, which executes in-session via \texttt{execute\_remedy\_plan} (\S\ref{sec:enforcement}) to apply label reductions or authorized rulings directly within the active session trajectory; and (2)~the \emph{explicit branch path}, which initiates a new host-requested child session bound to the parent-session reference, isolating restrictive data acquisition and child-local executions from the primary parent trajectory until an explicit merge or abandonment. Operating as a lightweight middleware, \appa{} leaves the underlying agent planning loop unmodified.

\paragraph{Planner representation and search state.}
The Remedy planner operates over a finite state abstraction $(L, \mathcal{E}(\ell))$ comprising the committed Label $L \in S$ and the family-wide committed-effect projection $\mathcal{E}(\ell) \subseteq K$. Because Labels descend over finite domains and committed effect kinds only accumulate, this representation defines a finite search state space. Over this state abstraction, the planner enumerates atomic \texttt{Authorize}/\texttt{Accept} executable plans alongside separately checked \texttt{Redispatch} recommendations for \texttt{prior(k)} emitters and cap-narrowing tools.

\paragraph{Transcript projection vs.\ shared log.}
Although all parent and child trajectories append events to a single family-wide serialized event log, transcript construction filters this log strictly by exact trajectory identifier. A child model transcript receives only the system/developer preamble and facts belonging directly to that child branch; it does not include parent user turns, assistant reasoning, or prior tool results. Consequently, a shared event log does not imply shared model-visible context: transcript projection remains strictly branch-local. History predicates evaluate over the family-wide committed-effect projection $\mathcal{E}$, while raw dispatch lifecycle facts remain preserved in the shared log for audit purposes.

The implementation prioritizes type invariants: invariants governing state transitions are enforced statically through the host language's type system~\cite{pierce2002types}, while external labels and authority decisions are treated as trusted inputs. When interfacing with partially annotated tool suites or host environments in Python or TypeScript, unannotated tool parameters default to \texttt{Unknown} and must pass through explicit boundary validators or cast resolvers before participating in label arithmetic. As an architectural design principle rather than a formal model claim, the policy checker avoids ad-hoc conditional logic; it restricts operations to label arithmetic and log predicates, delegating imperative execution to registered external components.

Branch lifecycle operations---\texttt{fork}, \texttt{submit}, \texttt{abandon}, and \texttt{merge}---include stable parent and child identifiers. Property-based tests generate arbitrary child execution traces to verify Proposition~\ref{prop:preservation}:
\begin{itemize}
  \item child-only actions cannot mutate the parent fold,
  \item a merge operation consists of exactly one meet with the submitted value's label, and
  \item all successfully committed effects remain visible in the family-wide projection following abandonment, while failed and indeterminate dispatch facts remain available for audit.
\end{itemize}

\fixme{The configuration surface is deliberately undecided; constraints that every surface must preserve are listed below.}
Configuration contains mandates exclusively, omitting grant objects entirely. It enforces a strict \emph{no-empty-mandate rule}: an authority with a mandate covering no permissions triggers an explicit configuration loading error, as the correctness proof for empty \texttt{remedy\_plans} relies on this invariant. Block messages expose applicable remedy plans and specify eligible authorities whenever a plan includes a ruling. Every audience specification explicitly declares its set relation---includes, exactly, or may-add---and scope routing is governed exclusively by tags. Type casts are restricted to constant definitions or resolver implementations.
