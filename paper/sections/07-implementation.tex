\section{Implementation}\label{sec:implementation}

APPA is divided into two distinct layers. The inner layer is a pure algebra that exposes \texttt{check(state, call)} $\mathbin{\to}$ \texttt{verdict} and \texttt{apply(state, call)} $\mathbin{\to}$ \texttt{state'}, performing no I/O operations and remaining independent of system time. Semantically, it evaluates decisions as a pure function of the complete event log, rendering every decision fully deterministic and replayable~\cite{schneider2000enforceable,wangAgentTracesTrust2026}. For state transmission, the implementation passes homomorphic views:
\begin{itemize}
  \item the folded state,
  \item seen event kinds,
  \item pending-plan records, and
  \item boundary positions---
\end{itemize}
which remains sound because each view is itself constructed as a fold~\cite{pierce2002types}.

The outer layer manages state persistence and system context. It handles durable append operations via pluggable storage backends (such as local files or databases), serialization, trajectory tree maintenance, and the dispatch-atomicity obligations assumed by the threat model. It creates child contexts, maintains their state isolated from the parent context, folds security labels independently across trajectories, and validates the return label prior to executing a \texttt{merge}. These guarantees are core security obligations enforced directly by the branch manager, rather than optional checks left to test harness authors.

\paragraph{Harness embeddability.}
Whereas structural frameworks like CaMeL demand a full architectural rewrite of the agent harness to enforce advance planning or multi-role pipelines~\cite{camel2025}, \appa{} is designed for surgical embedding into standard, single- or multi-agent runtimes. The integration surface requires only two pre-dispatch interceptor hooks: (1) branch lifecycle hooks to fork disposable contexts or merge/abandon results, and (2) sanitizer hooks to apply registered derivative functions. Because the underlying agent planner loop remains unmodified, \appa{} operates as a lightweight, embeddable middleware in existing real-world deployments.

The implementation prioritizes type invariants: invariants governing state transitions are enforced statically through the type system~\cite{pierce2002types}, while external labels and authority decisions are treated as trusted inputs. As an architectural design principle rather than a formal model claim, the policy checker avoids ad-hoc conditional logic; it restricts operations to label arithmetic and log predicates, delegating imperative execution to registered external components.

Branch lifecycle operations---\texttt{fork}, \texttt{submit}, \texttt{abandon}, and \texttt{merge}---include stable parent and child identifiers. Property-based tests generate arbitrary child execution traces to verify Proposition~\ref{prop:preservation}:
\begin{itemize}
  \item child-only actions cannot mutate the parent fold,
  \item a merge operation consists of exactly one meet with the submitted value's label, and
  \item all world events are preserved in the shared log following abandonment.
\end{itemize}

\fixme{The configuration surface is deliberately undecided; constraints that every surface must preserve are listed below.}
Configuration contains mandates exclusively, omitting grant objects entirely. It enforces a strict \emph{no-empty-mandate rule}: an authority with a mandate covering no permissions triggers an explicit configuration loading error, as the correctness proof for empty \texttt{remedy\_plans} relies on this invariant. Block messages expose applicable remedy plans and specify eligible authorities whenever a plan includes a ruling. Every audience specification explicitly declares its set relation---includes, exactly, or may-add---and scope routing is governed exclusively by tags. Type casts are restricted to constant definitions or resolver implementations.
