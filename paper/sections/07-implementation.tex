\section{Implementation}\label{sec:implementation}

\appa{} is implemented in two decoupled layers: an inner pure algebraic core that evaluates policy decisions deterministically over event log folds~\cite{schneider2000enforceable,wangAgentTracesTrust2026}, and an outer runtime that manages state persistence, context isolation, and dispatch hooks. State views (such as folded labels and pending plans) are passed homomorphically as log folds~\cite{pierce2002types}. The outer layer creates disposable child contexts, maintains trajectory isolation, and enforces return-label validation prior to merges.

\paragraph{Harness embeddability.}
Unlike frameworks requiring full harness rewrites~\cite{camel2025} or static capture checking~\cite{odersky2026tracking}, \appa{} embeds surgically into standard runtimes via two pre-dispatch interceptor hooks: (1)~branch lifecycle hooks (\texttt{fork}, \texttt{merge}, \texttt{abandon}), and (2)~sanitizer hooks for output transformations. Operating as a lightweight middleware, \appa{} leaves the underlying agent planning loop unmodified.

The implementation prioritizes type invariants: invariants governing state transitions are enforced statically through the host language's type system~\cite{pierce2002types}, while external labels and authority decisions are treated as trusted inputs. When interfacing with partially annotated tool suites or host environments in Python or TypeScript, unannotated tool parameters default to \texttt{Unknown} and must pass through explicit boundary validators or cast resolvers before participating in label arithmetic. As an architectural design principle rather than a formal model claim, the policy checker avoids ad-hoc conditional logic; it restricts operations to label arithmetic and log predicates, delegating imperative execution to registered external components.

Branch lifecycle operations---\texttt{fork}, \texttt{submit}, \texttt{abandon}, and \texttt{merge}---include stable parent and child identifiers. Property-based tests generate arbitrary child execution traces to verify Proposition~\ref{prop:preservation}:
\begin{itemize}
  \item child-only actions cannot mutate the parent fold,
  \item a merge operation consists of exactly one meet with the submitted value's label, and
  \item all world events are preserved in the shared log following abandonment.
\end{itemize}

\fixme{The configuration surface is deliberately undecided; constraints that every surface must preserve are listed below.}
Configuration contains mandates exclusively, omitting grant objects entirely. It enforces a strict \emph{no-empty-mandate rule}: an authority with a mandate covering no permissions triggers an explicit configuration loading error, as the correctness proof for empty \texttt{remedy\_plans} relies on this invariant. Block messages expose applicable remedy plans and specify eligible authorities whenever a plan includes a ruling. Every audience specification explicitly declares its set relation---includes, exactly, or may-add---and scope routing is governed exclusively by tags. Type casts are restricted to constant definitions or resolver implementations.
